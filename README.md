# 供应商归一核对页

招标数据维护员汇总中标公告时，同一家供应商可能以**现名**或**曾用名**出现；
缺少统一社会信用代码的记录不能随意合并。本工具输入中标公告目录 URL，
沿同站分页抓取详情页中的现名、曾用名与统一社会信用代码，按规则完成归一核对。

## 核对规则

1. **统一社会信用代码是权威依据**：代码相同（归一化后）的记录归入同一组。
2. **名称索引只由带代码记录建立**：带代码记录的现名/曾用名 → 代码组。
   无代码记录只读取该索引、绝不回写，因此**不可能借无代码记录把不同代码组串起来**。
3. **无代码记录**：
   - 所有名称唯一指向同一个代码组 → 归入该组（页面标注“无代码（按名称归入）”）；
   - 名称指向多个代码组 → 列为**待核实（同名多代码）**，给出候选代码；
   - 名称对不上任何代码组 → 列为**待核实（无法匹配）**。
4. 带代码记录之间若出现同名冲突（同一名称对应多个代码），该名称从索引剔除，
   后续同样按多义处理。
5. 页面按代码组展示组内全部名称与**每条记录的公告来源**（标题+可点击详情链接）；
   待核实记录单独成区，同样展示公告来源。
6. 任何页面抓取失败（404、连接失败、跨站重定向等）或达到抓取上限，
   页面顶部显示 **“名录可能不完整”** 警示，并附失败 URL 与原因清单。

## 抓取边界

- 仅访问 `http/https` 且与入口 URL **同站**（协议+主机[:端口]一致）的链接；
- 自动跟进分页与详情链接，静态资源（css/js/图片/文档等）不抓取；
- 跨站重定向按失败登记；
- 默认上限 100 个目录页 / 200 个详情页，超限置截断标记。

## 方式一：Docker Compose（推荐，完全离线）

```bash
docker compose up --build
```

- 核对页：<http://localhost:8000/>
- 示例站目录：<http://localhost:8080/list/index.html>

在核对页输入示例站目录 URL：

```
http://example-site:80/list/index.html     # 容器网络内访问
# 或从宿主机浏览器：
http://localhost:8080/list/index.html
```

两个镜像均为离线可用：应用基于 `python:3.11-slim`，**零第三方依赖**；
示例站基于 `nginx:alpine` 托管静态 HTML。

## 方式二：不用 Docker（本机有 Python 3.11+）

```bash
./run-local.sh
# 或手动：
python3 -m http.server 8080 --directory example-site/html
PYTHONPATH=. python3 -m app
```

核对页输入 `http://127.0.0.1:8080/list/index.html`。

## 示例站数据说明（example-site/html）

3 个目录分页、14 条公告链接（含 1 个 404 坏链），覆盖全部核对情形：

| 场景 | 对应公告 |
| --- | --- |
| 同代码、现名/曾用名两种写法归一组 | ann01/ann02、ann03/ann04/ann09、ann05/ann07/ann08 |
| 无代码、名称唯一命中 → 归入代码组 | ann10（归入华东智通组） |
| 无代码、两个名称各指向一个代码组 → 待核实，不串组 | ann12（候选：北辰组、云衡组） |
| 带代码同名冲突，无代码同名记录 → 待核实并列候选代码 | ann11 制造冲突，ann14 待核实 |
| 无代码且名称完全无法匹配 → 待核实 | ann13 |
| 详情页 404 → 失败登记 + 名录不完整提示 | missing-ann06 |
| 跨站链接不跟随 | about.html 中的外站链接 |

## 测试

```bash
# 全部为标准库 unittest；-I 隔离模式运行，避免被工作区污染
python3 -I -m unittest discover -s tests -v
```

测试包含名称/代码归一、分组与防串组不变量（含链式传播场景）、
四种 HTML 版式字段抽取，以及对示例站的真实 HTTP 端到端抓取（共 20 个用例）。

## 目录结构

```
app/
  htmltools.py   # 标准库 HTML 解析、链接与“标签:值”字段抽取
  normalize.py   # 名称/代码归一、代码组构建、待核实判定（核心规则）
  crawler.py     # 同站 BFS 抓取、分页跟进、失败登记、截断保护
  server.py      # http.server 页面与 /api/crawl 接口（内联前端，无外部资源）
example-site/
  html/          # 离线示例站静态页面
  nginx.conf     # 含 404 坏链配置
  Dockerfile
tests/           # 单元测试 + 端到端测试
docker-compose.yml
Dockerfile
run-local.sh
```
